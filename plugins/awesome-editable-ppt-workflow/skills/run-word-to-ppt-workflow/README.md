# Paginated Word to editable PowerPoint V6

Use `run-word-to-ppt-workflow` as the sole public workflow and `run-pages` as the formal page-generation command under prompt contract `awesome-page-design-v1`. A one-page run uses `run-pages --pages 1`. This development branch is not release-ready.

The workflow preserves complete page materials and opens one three-step confirmation UI. Step 1 confirms one whole-deck director template from five scenarios: Company & Business Introduction, Investment Committee, Project Initiation, Corporate Planning Report or Investment Project BP. Step 2 confirms three colors, CJK/Latin fonts and title/body/caption sizes. Step 3 confirms the seven-field presentation taskbook and the planned chapters, titles and ordered page structure.

Word remains the factual and per-page content authority. Planning reads the complete manuscript to derive chapters and titles. Original titles remain source material. Source pages cannot be deleted or reordered; proposed structure additions can be omitted in final confirmation. Lossless within-page rewording and regrouping must preserve every fact, explanation, condition and relationship. Template metadata never enters model prompts.

The new full-context page director produces one executable `page_plan.image_prompt`, sent to Image2 verbatim. The source inventory proves complete coverage; it does not assign layout slots. The independent reviewer may reject only one visible defect using exactly one of five hard-error categories: `fact_integrity`, `primary_relationship`, `core_exhibit_prominence`, `quantitative_truth`, or `severe_usability`. A structural page needs no invented conclusion. An `edit` correction uses the immediately previous image; a `replan` correction invokes the same new director. Both share the initial-plus-two-corrections budget. Old director records cannot be adopted as new-director output. Accepted pages resume only after signed authority verification; explicit failed-page recovery is bounded and multi-revision failure recovery remains unsupported.

Every reviewed body candidate is the final dynamic 17:8 crop uniformly resized to 1904x896. Accepted images then become the sole visual input to editable reconstruction and retain their body colors; fixed title, SVG Logo, footer and page number remain native layers outside Image2.
